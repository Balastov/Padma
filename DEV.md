## Сервер и конфигурация первой версии

`npm run dev` запускает Vite на 5173 и API на 3001; запросы `/api` проходят через Vite proxy. `npm run build` + `npm start` запускают готовый frontend и API на одном порту 3001. `npm run preview` отдельно backend не запускает.

База SQLite: `.data/padma.sqlite`, WAL и sessions рядом, всё исключено из git. Каталог создаётся с правами 0700. База содержит персональные данные и фото, сессии — хеши случайных токенов, пароли — scrypt с индивидуальной солью. Не размещать базу в `public` или `dist`.

Необязательные серверные переменные (пример в `.env.example`):

- `PADMA_DB`: путь к SQLite, по умолчанию `.data/padma.sqlite`.
- `PORT`: порт сервера, по умолчанию 3001. При смене в разработке нужно также обновить Vite proxy.
- `HOST`: адрес привязки, по умолчанию `127.0.0.1`.
- `APP_ORIGIN`: разрешённые origin через запятую для изменяющих запросов. Локально разрешены localhost/127.0.0.1 с портами 5173 и 3001. В production задавать только собственный HTTPS origin.
- `NODE_ENV=production`: включает Secure у cookie. Production должен работать через HTTPS.
- `VAPID_SUBJECT`: контакт для Web Push (mailto:…), по умолчанию `mailto:notify@padma.ru`. Ключи VAPID хранятся в `.data/vapid.json` и создаются при первом запуске.
- `OPENAI_API_KEY`: необязательный ключ для синтеза озвучки слов словаря (`POST /api/vocab` с `tts: true`). Без ключа аудио можно только загрузить вручную.
- `PADMA_TTS_VOICE`: голос OpenAI TTS (по умолчанию `alloy`).

`.env` автоматически не читается: передайте окружение процессу или используйте `node --env-file=.env.local server/index.mjs`. `VITE_*` не нужен, секретов в клиенте нет.

Сервер ограничивает размер запроса и попытки входа по адресу соединения, проверяет Origin и выдаёт HttpOnly/SameSite=Strict cookie со сроком 7 дней. При proxy это ограничение консервативно общее для адреса proxy; перед публичным запуском настройте внешний rate limit. API является источником прав, клиентские переходы не заменяют авторизацию.

Локальная инициализация двух аккаунтов: `npm run seed:doc -- "/путь/к/документу.docx"`. Скрипт использует macOS textutil, не выводит пароли и не сохраняет исходный документ. При повторном запуске существующие учётные записи пропускаются. На другой ОС следует подготовить отдельный безопасный инструмент provisioning, не коммитить пароли.

Шрифты хранятся локально с OFL-лицензиями в `public/fonts`. Внешних запросов к Google Fonts нет. Ссылка на Tolk требует интернета, интеграции с API Tolk нет.

Нынешний `vercel.json` относится к старой статической версии. Полная публикация использует Ubuntu: Node.js 24.21.0, systemd и постоянную SQLite. Конфигурации в `deploy/`, инструкция в DEPLOY.md. Vercel не используется для нового backend.

## Git и безопасный workflow

Сверка 16 сентября 2026: локальная main, origin/main и актуальная main на GitHub имели одинаковый commit `506b1875ae2bb67084bc5bf3529533546191dbbd` (first commit).
Удалённый HEAD указывал на main; других удалённых веток при проверке не было. До подготовки документации рабочая копия была чистой.
Remote origin: https://github.com/Balastov/Padma.git. Этот снимок может устареть — проверяйте состояние перед новой задачей.

1. Прочитайте AGENTS.md, проверьте `git status --short --branch` и `git diff`.
2. Если есть чужие изменения, сохраните их и согласуйте способ продолжения; не сбрасывайте и не прячьте их автоматически.
3. По умолчанию работайте в main (отдельные ветки — только по явной просьбе):

```bash
git fetch origin
git switch main
git pull --ff-only origin main
```

Если пользователь попросил отдельную ветку: `git switch -c feat/short-task-name` (или fix-/docs-). Если fast-forward невозможен, сначала разберите расхождение.

4. Одна законченная задача — небольшой набор изменений; не смешивайте её с обновлением всех зависимостей.
5. Выполните lint, build, необходимые ручные проверки и `git diff --check`.
6. После разрешения пользователя добавьте только нужные файлы (`git add <конкретные-файлы>`), проверьте `git diff --cached` и создайте осмысленный commit, например `docs: document local setup`.
7. По просьбе пользователя пушьте в `origin/main` (`git push origin main`). Push в main запускает автодеплой на Ubuntu — предупреждайте об этом при необходимости. Если работали в отдельной ветке, push ветки и merge согласуйте отдельно.

Нельзя применять force push, reset --hard, git clean или удаление веток без явной необходимости и разрешения.
Защита main и обязательные проверки на GitHub — возможный следующий шаг; сейчас они не настраивались.

## Проверки

```bash
npm run lint
npm run build
npm test
git diff --check
```

`npm test` запускает `node:test` с отдельной временной SQLite-базой и локальным HTTP-сервером. Проверяются вход/выход, cookies, запрет чужого Origin, разграничение ролей, невозможность повысить себе права, создание/архивирование пользователя, изменение пароля, пересечения и атомарность серии занятий, изоляция переписки и сохранение после открытия базы заново. Настоящая база и аккаунты заказчика не используются.

Проверки браузера:

- Вход по правильному и неправильному паролю, видимость пароля, выход через меню.
- Учитель: свои ученики; владелец/администратор: полный справочник. Поиск, создание, сохранение, перезагрузка, выбор преподавателя, фото.
- Создание занятия, обязательные поля и порядок времени, конфликт, неделя/список, переходы по неделям, повторение и отмена одного занятия.
- Ученик: преподаватель, ближайший урок, общая ссылка Tolk, недельное расписание, сообщение и его сохранение после reload.
- Ученик без учителя: отдельный портрет-заглушка, подпись и отсутствие чата до назначения.
- Ширины 390, 768, 1024 и 1440 px: отсутствие горизонтального переполнения страницы, доступность форм, мобильный список вместо сетки календаря.
- Пользователи в другом часовом поясе также видят московские даты/часы.
- Tab/Escape в диалоге, возврат фокуса, отсутствие ошибок браузера.

В браузере: выдача → отправка PDF → скачивание → возврат → повторная сдача → принятие на ширинах 390/768/1440 px.

## Справочник лексики (учебники)

`server/lexicon.mjs` — справочник слов из учебников, отдельный от банка слов преподавателя (`server/vocab.mjs`). Таблицы: `lexicon_books` (учебник, уровень), `lexicon_units` (номер юнита в учебнике и ссылка `topicId` на тему `vocab_topics`), `lexicon_terms` (уникальный термин без учёта регистра, перевод, основная транскрипция), `lexicon_occurrences` (термин в юните: контекстное предложение и транскрипция из этого учебника).

Импорт из XLSX (первый лист, колонки ищутся по заголовкам: Термин, Перевод, Контекстное предложение, Учебник, Уровень книги, Юнит, Тема, Транскрипция…):

```bash
npm run import:lexicon -- /путь/к/lexicon.xlsx            # пустой справочник
npm run import:lexicon -- /путь/к/lexicon.xlsx --replace  # полная замена, ручные правки теряются
```

Тема — общая сущность со страницей «Лексика → Словарь → Темы» (`vocab_topics`): при импорте темы находятся по названию без учёта регистра или создаются (тип «Основная тема», автор — первый владелец/администратор/преподаватель). Юниты, загруженные до появления связи, привязываются при старте сервера. `lexicon_units.theme` хранит копию названия и обновляется при переименовании темы. Названия тем уникальны без учёта регистра и лишних пробелов, подтем — в пределах темы (409 при дубле); тему, используемую юнитами, удалить нельзя.

Скрипт использует `PADMA_DB`, без внешних зависимостей (`server/xlsx.mjs`). При ошибках в строках (нет термина/учебника/темы, нецелый юнит, у юнита разные темы) база не меняется. Слэши вокруг транскрипции убираются, полные дубли (термин + юнит + предложение) пропускаются. Идентификаторы терминов детерминированы (хеш термина) и сохраняются при повторном импорте; идентификаторы вхождений — нет.

API (чтение — любой вошедший пользователь, правка — учитель/администратор):

- `GET /api/lexicon/books` — учебники с юнитами, темами и числом слов.
- `GET /api/lexicon/themes` — все темы (id, название, число слов из учебников, юниты).
- `GET /api/lexicon/units/:id` — слова юнита (`id` вида `elementary-25`).
- `GET /api/lexicon/entries?q=&bookId=&unitId=&topicId=&theme=&limit=&offset=` — постраничные строки «термин в юните», как в исходной таблице (по умолчанию 20, до 200; `bookId` можно повторять для нескольких учебников); используется страницей «Лексика → Словарь → Все слова».
- `GET /api/lexicon/search?q=&bookId=&unitId=&theme=&limit=&offset=` — поиск по термину и переводу (подстрока, без учёта регистра), фильтры, `limit` до 200.
- `GET|PATCH /api/lexicon/terms/:id` — карточка термина со всеми вхождениями; правка `term`, `translation`, `transcription`.
- `PATCH /api/lexicon/occurrences/:id` — правка `sentence`, `transcription` вхождения.

Слова подтем учитель выбирает сам на странице «Темы» (`lexicon_subtopic_terms`; у termId нет внешнего ключа, поэтому выбор переживает импорт с --replace). Слова темы = слова её юнитов учебников + слова её подтем. API (только преподаватель): `GET /api/lexicon/topics/:id/terms` (подтемы и слова темы), `GET|POST /api/lexicon/subtopics/:id/terms` (`{ termIds }`), `DELETE /api/lexicon/subtopics/:id/terms/:termId`.

Лексика в ДЗ: `POST /api/homework` принимает `lexicon: [{ kind: 'topic'|'subtopic'|'search', id?, termIds }]`. Сервер проверяет, что слова принадлежат источнику, убирает повторы внутри задания (ответ `duplicatesSkipped`) и сохраняет снимок слов (`homework_terms`) и источников (`homework_lexicon_sources`) — правки словаря не меняют выданные задания. Коллекции и «Слова уроков» пока отклоняются. В выдаче ДЗ поле `lexicon: { sources, words }`.

`server/lexicon.test.mjs` проверяет чтение XLSX, валидацию и защиту от повторного импорта, выдачу API, поиск по-русски и по-английски, запрет правок ученику.

## Учебники: темы, подтемы и слова из файлов по книгам

`npm run import:book -- /путь/к/книге.xlsx [--dry-run] [--book=<id>]` (`server/lexiconBook.mjs`) — выверенный файл по одному учебнику (English Vocabulary in Use). Первый лист называется как учебник (`Elementary` → `elementary`), колонки: Тема, № юнита, Подтема, Категория, Тип, Слово / выражение, Транскрипция, Перевод, Пример, Перевод примера. Остальные листы (навигация, QC) игнорируются. Сначала запускайте с `--dry-run`: база не меняется, печатается план.

Файл становится источником истины для своего учебника:
- Темы получают английские названия. Тема, используемая только этим учебником, переименовывается на месте (id, ручные подтемы сохраняются, старое название пишется в описание «Ранее: …»); общая с другим учебником — остаётся ему, для этой книги создаётся новая. Одинаковое английское название в разных учебниках получает уровень у обоих: «People (A1-A2)», «People (A2-B1)».
- На каждый юнит — подтема «N. Название юнита» (`vocab_subtopics.lexiconUnitId`) со словами юнита в порядке файла. Подтемы сортируются по номеру, ручные — после них.
- Вхождения юнитов заменяются данными файла: перевод, транскрипция, пример и его перевод, часть речи, категория хранятся у вхождения (`lexicon_occurrences`) и имеют приоритет над общими полями термина; поиск учитывает перевод юнита. Термины, которые больше нигде не используются, удаляются. Выданные ДЗ хранят снимок и не меняются.
- Повторный запуск безопасен: тот же результат, те же id подтем; ручные правки слов сгенерированных подтем перезаписываются.

Внимание: `npm run import:lexicon -- … --replace` (исходная общая таблица) перезапишет эти данные — после загрузки файлов по книгам его не используйте. `server/lexiconBook.test.mjs` проверяет проверку файла и dry-run, переименование тем на месте, подтемы по юнитам и их порядок, перевод юнита и поиск по нему, общую с другим учебником тему, уровни у одноимённых тем, снимок в ДЗ и повторный запуск.

## Словарь ученика: «Мои слова → Словарь → Темы»

Ученик видит все темы словаря учебников (`server/lexiconStudent.mjs`, `src/pages/words/LexiconTopicsPage.tsx`, `LexiconSubtopicPage.tsx`); фильтр «Уровень» (учебник) запоминается в браузере. API (любой вошедший пользователь, прогресс — свой):

- `GET /api/lexicon/me/topics?bookId=` — темы со словами: число слов, подтем, прогресс.
- `GET /api/lexicon/me/topics/:id?bookId=` — тема и её подтемы (подтемы юнитов выбранных учебников и ручные подтемы) с прогрессом.
- `GET /api/lexicon/me/subtopics/:id` — слова подтемы с переводом и примером юнита, уровнем и статусом ученика. Шаблонные предложения исходной таблицы («We used … in class today») и служебное описание темы «Ранее: …» ученику не показываются.
- `POST /api/lexicon/me/progress` `{ results: [{ termId, correct }] }` — результаты тренажёра; статусы как в тренажёре: Новое → Изучается → Закрепляется → Освоено, ошибка возвращает на «Изучается»/«Закрепляется» (`lexicon_progress`). Процент = доля изученного с весами 0, ⅓, ⅔, 1.

Тренажёр («Темы» и кнопка «В тренажёр») берёт слова подтем словаря: они попадают в каталог тренажёра с id `lx:<termId>`, сессия хранит их снимок, ответы пакетами уходят на сервер (`src/student/lexicon.ts`). Сначала тренируются неосвоенные слова. В словаре вкладки «Слова уроков» и «Коллекции» — заглушки (`DictionaryStubs.tsx`), «Лексические группы» помечены как раздел на доработке. Страница слов подтемы: таблица без отметок, карточка с местом под картинку и примером (кнопка озвучивает всё предложение), «Связанные слова» — следующие слова подтемы. В тренажёре «Все слова», «Слова уроков» и «Коллекции» пока работают с банком слов преподавателя; страница «Прогресс» — с локальной статистикой. Иконки и цвета тем подбираются по названию (`topicIcons.ts`), фото тем — следующий этап. `server/lexiconStudent.test.mjs` проверяет видимость и фильтр уровня, подтемы и слова, скрытие шаблонов, шаги статусов, проценты и изоляцию прогресса учеников.

## Оформление: Liquid Glass и фон

Стеклянные поверхности задаются переменными в `src/styles/global.css` (`--glass-fill`, `--glass-fill-strong`, `--glass-blur`, `--glass-rim`, `--glass-shadow`) и классами `.glass` / `.glass-panel`. Важно: при значении через `var()` Lightning CSS оставляет только последнее из пары `backdrop-filter` / `-webkit-backdrop-filter`, поэтому префиксная версия пишется первой, стандартная — последней. `global.css` подключается после CSS компонентов, поэтому переопределения поверх `.glass-panel` требуют более точного селектора.

`server/appearance.mjs`: таблица `appearance` (owner = id преподавателя или `default`, изображение BLOB до 5 МБ JPG/PNG/WebP с проверкой сигнатуры, размытие 0–60, осветление 0–90). Преподаватель видит свой фон, ученик — фон своего преподавателя, остальные и страница входа — фон по умолчанию. API: `GET /api/appearance` (активный фон и права), `PUT|DELETE /api/appearance/mine` (только роль teacher), `PUT|DELETE /api/appearance/default` (owner/admin), `GET /api/appearance/image/:owner?v=` (версионированный URL, долгий кэш; фон по умолчанию и `GET /api/appearance/public` доступны без входа). Браузер перед загрузкой уменьшает фото до 2560 px и перекодирует в JPEG. Настройки — раздел «Оформление» на странице «Настройки» преподавателя; ползунки показывают предпросмотр на всём сайте до сохранения. `server/appearance.test.mjs` проверяет права, видимость фона по ролям, валидацию и сохранение настроек без замены изображения.
