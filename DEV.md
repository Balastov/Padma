## Сервер и конфигурация первой версии

`npm run dev` запускает Vite на 5173 и API на 3001; запросы `/api` проходят через Vite proxy. `npm run build` + `npm start` запускают готовый frontend и API на одном порту 3001. `npm run preview` отдельно backend не запускает.

База SQLite: `.data/padma.sqlite`, WAL и sessions рядом, всё исключено из git. Каталог создаётся с правами 0700. База содержит персональные данные и фото, сессии — хеши случайных токенов, пароли — scrypt с индивидуальной солью. Не размещать базу в `public` или `dist`.

Необязательные серверные переменные (пример в `.env.example`):

- `PADMA_DB`: путь к SQLite, по умолчанию `.data/padma.sqlite`.
- `PADMA_FILES`: папка для файлов ДЗ, чата и библиотеки, по умолчанию `files` рядом с базой.
- `PORT`: порт сервера, по умолчанию 3001. При смене в разработке нужно также обновить Vite proxy.
- `HOST`: адрес привязки, по умолчанию `127.0.0.1`.
- `APP_ORIGIN`: разрешённые origin через запятую для изменяющих запросов. Локально разрешены localhost/127.0.0.1 с портами 5173 и 3001. В production задавать только собственный HTTPS origin.
- `NODE_ENV=production`: включает Secure у cookie. Production должен работать через HTTPS.
- `VAPID_SUBJECT`: контакт для Web Push (mailto:…), по умолчанию `mailto:notify@padma.ru`. Ключи VAPID хранятся в `.data/vapid.json` и создаются при первом запуске.
- `OPENAI_API_KEY`: необязательный ключ для синтеза озвучки слов словаря (`POST /api/vocab` с `tts: true`). Без ключа аудио можно только загрузить вручную.
- `PADMA_TTS_VOICE`: голос OpenAI TTS (по умолчанию `alloy`).

`.env` автоматически не читается: передайте окружение процессу или используйте `node --env-file=.env.local server/index.mjs`. `VITE_*` не нужен, секретов в клиенте нет.

Сервер ограничивает размер запроса и попытки входа по адресу соединения, проверяет Origin и выдаёт HttpOnly/SameSite=Strict cookie со сроком 7 дней. При proxy это ограничение консервативно общее для адреса proxy; перед публичным запуском настройте внешний rate limit. API является источником прав, клиентские переходы не заменяют авторизацию.

Локальная инициализация двух аккаунтов: `npm run seed:doc -- "/путь/к/документу.docx"`. Скрипт использует macOS textutil, не выводит пароли и не сохраняет исходный документ. При повторном запуске существующие учётные записи пропускаются. На другой ОС следует подготовить отдельный безопасный инструмент provisioning, не коммитить пароли.

Шрифты хранятся локально с OFL-лицензиями в `public/fonts`. Внешних запросов к Google Fonts нет. Ссылка на Tolk требует интернета, интеграции с API Tolk нет.

Нынешний `vercel.json` относится к старой статической версии. Полная публикация использует Ubuntu: Node.js 24.21.0, systemd и постоянную SQLite. Конфигурации в `deploy/`, инструкция в DEPLOY.md. Vercel не используется для нового backend.

## Git и безопасный workflow

Сверка 16 сентября 2026: локальная main, origin/main и актуальная main на GitHub имели одинаковый commit `506b1875ae2bb67084bc5bf3529533546191dbbd` (first commit).
Удалённый HEAD указывал на main; других удалённых веток при проверке не было. До подготовки документации рабочая копия была чистой.
Remote origin: https://github.com/Balastov/Padma.git. Этот снимок может устареть — проверяйте состояние перед новой задачей.

1. Прочитайте AGENTS.md, проверьте `git status --short --branch` и `git diff`.
2. Если есть чужие изменения, сохраните их и согласуйте способ продолжения; не сбрасывайте и не прячьте их автоматически.
3. По умолчанию работайте в main (отдельные ветки — только по явной просьбе):

```bash
git fetch origin
git switch main
git pull --ff-only origin main
```

Если пользователь попросил отдельную ветку: `git switch -c feat/short-task-name` (или fix-/docs-). Если fast-forward невозможен, сначала разберите расхождение.

4. Одна законченная задача — небольшой набор изменений; не смешивайте её с обновлением всех зависимостей.
5. Выполните lint, build, необходимые ручные проверки и `git diff --check`.
6. После разрешения пользователя добавьте только нужные файлы (`git add <конкретные-файлы>`), проверьте `git diff --cached` и создайте осмысленный commit, например `docs: document local setup`.
7. По просьбе пользователя пушьте в `origin/main` (`git push origin main`). Push в main запускает автодеплой на Ubuntu — предупреждайте об этом при необходимости. Если работали в отдельной ветке, push ветки и merge согласуйте отдельно.

Нельзя применять force push, reset --hard, git clean или удаление веток без явной необходимости и разрешения.
Защита main и обязательные проверки на GitHub — возможный следующий шаг; сейчас они не настраивались.

## Проверки

```bash
npm run lint
npm run build
npm test
git diff --check
```

`npm test` запускает `node:test` с отдельной временной SQLite-базой и локальным HTTP-сервером. Проверяются вход/выход, cookies, запрет чужого Origin, разграничение ролей, невозможность повысить себе права, создание/архивирование пользователя, изменение пароля, пересечения и атомарность серии занятий, изоляция переписки и сохранение после открытия базы заново. Настоящая база и аккаунты заказчика не используются.

Проверки браузера:

- Вход по правильному и неправильному паролю, видимость пароля, выход через меню.
- Учитель: свои ученики; владелец/администратор: полный справочник. Поиск, создание, сохранение, перезагрузка, выбор преподавателя, фото.
- Создание занятия и серии (дни, время по дням, окончание, план тем), обязательные поля и порядок времени, пересечения («Без этих дат», «С пересечениями»), неделя/список, переходы по неделям. Диалог урока: «Отменить урок», «Неявка», «Вернуть в расписание», «Изменить урок», «Изменить серию» (с урока / все), «Удалить» (этот / этот и следующие / все); сдвиг тем и продление пакета в календаре.
- Ученик: преподаватель, ближайший урок, общая ссылка Tolk, недельное расписание, сообщение и его сохранение после reload.
- Ученик без учителя: без портрета, подпись «Скоро вам назначат учителя» и отсутствие чата до назначения; портрет учителя появляется без промежуточной заглушки.
- Ширины 390, 768, 1024 и 1440 px: отсутствие горизонтального переполнения страницы, доступность форм, мобильный список вместо сетки календаря.
- Пользователи в другом часовом поясе также видят московские даты/часы.
- Tab/Escape в диалоге, возврат фокуса, отсутствие ошибок браузера.

## Повторяющиеся уроки

`server/lessons.mjs`. Серия (`lesson_series`) хранит правило: дата начала, `everyWeeks` (1–12), дни недели со своим временем (`days: [{ weekday: 1–7, start, end }]`), окончание `never | until | count` (до 2 лет или до 200 уроков) и план тем. Каждый урок серии — обычная строка `lessons` (к id урока привязаны слова урока) с `seriesId` и `occurrence` — исходным слотом правила `YYYY-MM-DDTHH:MM-HH:MM`, поэтому перенесённый урок остаётся своим слотом. Бессрочные серии создаются на 16 недель вперёд и продлеваются при `GET /api/lessons`. Начало серии — не раньше 60 дней назад.

Статусы урока: `scheduled`, `cancelled` («Отменён», не оплачивается), `noshow` («Неявка», оплачивается). Оба освобождают время. Темы плана идут по запланированным урокам по порядку (`seq` — номер урока), поэтому отмена, неявка и удаление сдвигают темы вправо; урок со своей темой (`customTitle`) заменяет плановую, и она переходит дальше. В серии «N уроков» отменённые и удалённые уроки добавляются в конец, неявка засчитывается; возврат отменённого урока убирает лишний последний. Прошедшие уроки при перестройке серии не меняются; будущие переиспользуются по порядку (id и слова урока сохраняются).

API: `GET /api/lessons`; `GET /api/lesson-series`; `POST /api/lessons` (без `recurrence` — один урок, с `recurrence: { everyWeeks, days, endType, until, count, plan }` — серия от `date`); `PATCH /api/lessons/:id` — только этот урок (пустая тема в серии возвращает тему из плана); `POST /api/lessons/:id/status { status }`; `PUT /api/lesson-series/:id { scope: 'all' | 'following', fromLessonId, startDate, title, note, recurrence }` — «этот и следующие» заканчивает старую серию накануне урока и продолжает нумерацию, план и пакет в новой; `DELETE /api/lessons/:id { scope: 'this' | 'following' | 'all' }`. При пересечении ответ 409 `{ error, conflicts: [{ date, start, end, busyStart, busyEnd }] }`; повтор с `conflicts: 'skip'` (только серии) или `'overlap'`. Выбранный режим запоминается для автопродления серии (по умолчанию конфликтные даты пропускаются). `server/lessons.test.mjs` проверяет правила, сдвиг тем, статусы, пакет, пересечения, «все» / «этот и следующие», удаление и права.

Ограничения: серия привязана к учителю, который был у ученика при создании; смена учителя ученику не переносит серию. Паузы «на каникулы» нет — её заменяют отмена уроков или окончание «до даты».

## Файлы

`server/files.mjs`. Файлы лежат на диске в `PADMA_FILES` (по умолчанию папка `files` рядом с `PADMA_DB`: локально `.data/files`, на сервере `/var/lib/padma/files`), в базе — только таблица `files` (имя, размер, владелец, к чему привязан, срок). Разрешены изображения (JPG, PNG, GIF, WebP, HEIC), PDF, DOC/DOCX, XLS/XLSX, PPT/PPTX, ODT/ODS/ODP, RTF, CSV и TXT, до 20 МБ каждый; аудио, видео и архивы запрещены. Проверка по расширению, имя на диске — случайный id.

Загрузка в два шага: `POST /api/files?name=<имя>` с телом-файлом (`application/octet-stream`) создаёт «ожидающий» файл владельца (живёт 24 часа, не больше 30 одновременно), затем его id передаётся в `fileIds` задания, ответа, сообщения чата или в `fileId` материала библиотеки. Чужой или уже прикреплённый файл прикрепить нельзя. `GET /api/files/:id` проверяет доступ тем же правилом, что и для задания, переписки или материала; PDF и картинки открываются в браузере, остальное скачивается (`?download` — всегда скачать).

Файлы ДЗ и чата удаляются через 30 дней после загрузки: сервер проверяет сроки при старте и каждый час, запись остаётся, и интерфейс пишет «удалён, файлы хранятся 30 дней» (ответ 410). Материалы библиотеки хранятся, пока их не удалят. Старые вложения ДЗ из SQLite (таблица `homework_files`) при первом запуске переносятся на диск; для них 30 дней отсчитываются от переноса. Резервная копия (`scripts/backup.mjs`) сохраняет только базу — файлы на диске в неё не входят.

Библиотека (`server/library.mjs`): `GET|POST /api/library`, `DELETE /api/library/:id`. Материал — название, описание, один файл и аудитория: «всем моим ученикам» (у владельца/администратора — всем ученикам школы) или выбранным ученикам. Учитель видит и удаляет свои материалы, владелец/администратор — все. Чат: `POST /api/messages/:peer` принимает `fileIds`, сообщение может состоять только из файлов.

`server/files.test.mjs` проверяет перенос старых вложений, файлы чата и права на них, видимость библиотеки, удаление через 30 дней и удаление материала с файлом; `server/homework.test.mjs` — типы и размер, чужие файлы, PDF в браузере и скачивание, 410 после срока.

## Домашние задания

`server/homework.mjs` создаёт дополнительные таблицы без изменения существующих данных: homework, submissions. Файлы задания и ответа — через общее хранилище (раздел «Файлы»), `fileIds` в `POST /api/homework` и `POST /api/homework/:id/submit`.

API: GET/POST `/api/homework`, POST `/api/homework/:id/submit`, POST `/api/homework/:id/review`. Проверка принимает идентификатор конкретной отправки; устаревшие и повторные проверки возвращают 409. Проверки типа ограничены расширением; проверки содержимого антивирусом нет.

`server/homework.test.mjs` проверяет весь цикл, ограничения файлов, чужой доступ, смену преподавателя, архивирование, повторные запросы и сохранение истории/файлов после повторного открытия базы. В браузере: выдача → отправка PDF → скачивание → возврат → повторная сдача → принятие на ширинах 390/768/1440 px.

## Справочник лексики (учебники)

`server/lexicon.mjs` — справочник слов из учебников, отдельный от банка слов преподавателя (`server/vocab.mjs`). Таблицы: `lexicon_books` (учебник, уровень), `lexicon_units` (номер юнита в учебнике и ссылка `topicId` на тему `vocab_topics`), `lexicon_terms` (уникальный термин без учёта регистра, перевод, основная транскрипция), `lexicon_occurrences` (термин в юните: контекстное предложение и транскрипция из этого учебника).

Импорт из XLSX (первый лист, колонки ищутся по заголовкам: Термин, Перевод, Контекстное предложение, Учебник, Уровень книги, Юнит, Тема, Транскрипция…):

```bash
npm run import:lexicon -- /путь/к/lexicon.xlsx            # пустой справочник
npm run import:lexicon -- /путь/к/lexicon.xlsx --replace  # полная замена, ручные правки теряются
```

Тема — общая сущность со страницей «Лексика → Словарь → Темы» (`vocab_topics`): при импорте темы находятся по названию без учёта регистра или создаются (тип «Основная тема», автор — первый владелец/администратор/преподаватель). Юниты, загруженные до появления связи, привязываются при старте сервера. `lexicon_units.theme` хранит копию названия и обновляется при переименовании темы. Названия тем уникальны без учёта регистра и лишних пробелов, подтем — в пределах темы (409 при дубле); тему, используемую юнитами, удалить нельзя.

Скрипт использует `PADMA_DB`, без внешних зависимостей (`server/xlsx.mjs`). При ошибках в строках (нет термина/учебника/темы, нецелый юнит, у юнита разные темы) база не меняется. Слэши вокруг транскрипции убираются, полные дубли (термин + юнит + предложение) пропускаются. Идентификаторы терминов детерминированы (хеш термина) и сохраняются при повторном импорте; идентификаторы вхождений — нет.

API (чтение — любой вошедший пользователь, правка — учитель/администратор):

- `GET /api/lexicon/books` — учебники с юнитами, темами и числом слов.
- `GET /api/lexicon/themes` — все темы (id, название, число слов из учебников, юниты).
- `GET /api/lexicon/units/:id` — слова юнита (`id` вида `elementary-25`).
- `GET /api/lexicon/entries?q=&bookId=&unitId=&topicId=&theme=&limit=&offset=` — постраничные строки «термин в юните», как в исходной таблице (по умолчанию 20, до 200; `bookId` можно повторять для нескольких учебников); используется страницей «Лексика → Словарь → Все слова».
- `GET /api/lexicon/search?q=&bookId=&unitId=&theme=&limit=&offset=` — поиск по термину и переводу (подстрока, без учёта регистра), фильтры, `limit` до 200.
- `GET|PATCH /api/lexicon/terms/:id` — карточка термина со всеми вхождениями; правка `term`, `translation`, `transcription`.
- `PATCH /api/lexicon/occurrences/:id` — правка `sentence`, `transcription` вхождения.

Слова подтем учитель выбирает сам на странице «Темы» (`lexicon_subtopic_terms`; у termId нет внешнего ключа, поэтому выбор переживает импорт с --replace). Слова темы = слова её юнитов учебников + слова её подтем. API (только преподаватель): `GET /api/lexicon/topics/:id/terms` (подтемы и слова темы), `GET|POST /api/lexicon/subtopics/:id/terms` (`{ termIds }`), `DELETE /api/lexicon/subtopics/:id/terms/:termId`.

Лексика в ДЗ: `POST /api/homework` принимает `lexicon: [{ kind: 'topic'|'subtopic'|'search', id?, termIds }]`. Сервер проверяет, что слова принадлежат источнику, убирает повторы внутри задания (ответ `duplicatesSkipped`) и сохраняет снимок слов (`homework_terms`) и источников (`homework_lexicon_sources`) — правки словаря не меняют выданные задания. Коллекции и «Слова уроков» пока отклоняются. В выдаче ДЗ поле `lexicon: { sources, words }`.

`server/lexicon.test.mjs` проверяет чтение XLSX, валидацию и защиту от повторного импорта, выдачу API, поиск по-русски и по-английски, запрет правок ученику.

## Публикация и backup

`bash scripts/deploy.sh` — ручной деплой чистого закоммиченного состояния. `deploy/activate.sh` переключает выпуск с проверкой работы и откатом при ошибке. `scripts/backup.mjs` принимает PADMA_DB и PADMA_BACKUP_DIR, сохраняет 14 проверенных снимков SQLite. `server/backup.test.mjs` проверяет копию при активном WAL и приватные права файла. Серверный Node 24 повторно выполняет весь набор тестов перед активацией.

## Учебники: темы, подтемы и слова из файлов по книгам

`npm run import:book -- /путь/к/книге.xlsx [--dry-run] [--book=<id>]` (`server/lexiconBook.mjs`) — выверенный файл по одному учебнику (English Vocabulary in Use). Первый лист называется как учебник (`Elementary` → `elementary`), колонки: Тема, № юнита, Подтема, Категория, Тип, Слово / выражение, Транскрипция, Перевод, Пример, Перевод примера. Остальные листы (навигация, QC) игнорируются. Сначала запускайте с `--dry-run`: база не меняется, печатается план.

Файл становится источником истины для своего учебника:
- Темы получают английские названия. Тема, используемая только этим учебником, переименовывается на месте (id, ручные подтемы сохраняются, старое название пишется в описание «Ранее: …»); общая с другим учебником — остаётся ему, для этой книги создаётся новая. Одинаковое английское название в разных учебниках получает уровень у обоих: «People (A1-A2)», «People (A2-B1)».
- На каждый юнит — подтема «N. Название юнита» (`vocab_subtopics.lexiconUnitId`) со словами юнита в порядке файла. Подтемы сортируются по номеру, ручные — после них.
- Вхождения юнитов заменяются данными файла: перевод, транскрипция, пример и его перевод, часть речи, категория хранятся у вхождения (`lexicon_occurrences`) и имеют приоритет над общими полями термина; поиск учитывает перевод юнита. Термины, которые больше нигде не используются, удаляются. Выданные ДЗ хранят снимок и не меняются.
- Повторный запуск безопасен: тот же результат, те же id подтем; ручные правки слов сгенерированных подтем перезаписываются.

Внимание: `npm run import:lexicon -- … --replace` (исходная общая таблица) перезапишет эти данные — после загрузки файлов по книгам его не используйте. `server/lexiconBook.test.mjs` проверяет проверку файла и dry-run, переименование тем на месте, подтемы по юнитам и их порядок, перевод юнита и поиск по нему, общую с другим учебником тему, уровни у одноимённых тем, снимок в ДЗ и повторный запуск.

## Словарь ученика: «Мои слова → Словарь → Темы»

Ученик видит все темы словаря учебников (`server/lexiconStudent.mjs`, `src/pages/words/LexiconTopicsPage.tsx`, `LexiconSubtopicPage.tsx`); фильтр «Уровень» (учебник) запоминается в браузере. API (любой вошедший пользователь, прогресс — свой):

- `GET /api/lexicon/me/topics?bookId=` — темы со словами: число слов, подтем, прогресс.
- `GET /api/lexicon/me/topics/:id?bookId=` — тема и её подтемы (подтемы юнитов выбранных учебников и ручные подтемы) с прогрессом.
- `GET /api/lexicon/me/subtopics/:id` — слова подтемы с переводом и примером юнита, уровнем и статусом ученика. Шаблонные предложения исходной таблицы («We used … in class today») и служебное описание темы «Ранее: …» ученику не показываются.
- `POST /api/lexicon/me/progress` — ответы тренажёра, см. «Прогресс слов» ниже. Статус слова выводится из Mastery: Новое (попыток не было), Изучается (< 40), Закрепляется (40–89), Освоено (≥ 90). Процент темы — средний Mastery слов, освоенное слово считается целиком (`min(1, mastery / 90)`).

Тренажёр («Темы» и кнопка «В тренажёр») берёт слова подтем словаря: они попадают в каталог тренажёра с id `lx:<termId>`, сессия хранит их снимок, ответы пакетами уходят на сервер (`src/student/lexicon.ts`). Сначала тренируются неосвоенные слова. В словаре вкладки «Слова уроков» и «Коллекции» — заглушки (`DictionaryStubs.tsx`), «Лексические группы» помечены как раздел на доработке. Страница слов подтемы: таблица без отметок, карточка с местом под картинку и примером (кнопка озвучивает всё предложение), «Связанные слова» — следующие слова подтемы. Главная тренажёра: набор слов выбирается из «Домашнего задания» (`GET /api/lexicon/me/homework` — свои ДЗ «К выполнению» и «Нужна доработка» со словами; слова — `GET /api/lexicon/me/homework/:id/words`, перевод из снимка ДЗ, примеры из словаря) или «Моих коллекций» (пока локальные и пустые); одно исключает другое. Ссылка «В тренажёр» из словаря подставляет подтему. В занятии до 12 слов, сначала неосвоенные. Рамка занятия: контекст, таймер с открытия формата, «Слова в этом занятии» (✓ верно, ✗ ошибка или пропуск, текущее, в очереди), «Пропустить» и «Выйти из тренажёра» — сбрасывает попытку; пауза с сохранением (`resumable`) включится для ДЗ, привязанных к урокам программы, — такой связи пока нет, поэтому и плашки «Текущий урок» нет. Результат: процент, время, серия дней (с сервера, текущее занятие засчитывается сразу), трудные слова и «Повторить сложные слова». Неизвестные словарю слова в пакете прогресса пропускаются. Форматы этапа 3 (`exercises.tsx`): «Карточки» (слово и пример озвучиваются отдельно, перевод в поле по кнопке), «Тренировочные карточки» (Легко — верно, Сложно — ошибка, Пропустить), «Собери слово» и «· аудио» (плитки — перемешанные буквы, только буквы/апостроф/дефис, ячейки по словам выражения; Перемешать, Отменить, Проверить, Пропустить), «Выбери перевод» и «· аудио» (верный и 3 других перевода из занятия), «Верно — неверно» (перевод верный с вероятностью 50 %; «Выбрать»). Ответ даётся один раз: похвала или правильный ответ с пожеланием удачи, затем «Дальше». Аудиоверсии сами произносят слово. В списке «Слова в этом занятии» до ответа скрыто то, что является ответом формата (слово или перевод). Картинки — заглушки. Игры этапа 4 (`games.tsx`): «Найди слово» — сетка 10×8, слово по горизонтали, вертикали или «змейкой» только с поворотами под 90°, выделение щелчками по соседним клеткам, подсказка первой буквы прибавляет 1 минуту к таймеру занятия; «Собери пару» — шаги по ≤ 6 пар примерно поровну, связи линиями, «Отменить» последнюю связь, «Проверить»; «Мемория» — 4×3 (6 пар), рубашка с лотосом, открытая карта озвучивается (en/ru), «Идеальная пара!» / «Попробуй ещё раз», угаданные пары заменяются следующими (если слов больше 6), «Пропустить». Лучшее время «Мемории» — `trainer_records`, `GET|POST /api/lexicon/me/records/memory` (лучшее за все попытки, место среди учеников без имён). Рамка принимает ответы пачкой (игры), статусы списка привязаны к слову. Страница «Прогресс» — см. «Прогресс слов». Иконки и цвета тем подбираются по названию (`topicIcons.ts`), фото тем — следующий этап. `server/lexiconStudent.test.mjs` проверяет видимость и фильтр уровня, подтемы и слова, скрытие шаблонов, шаги статусов, проценты и изоляцию прогресса учеников.

## Прогресс слов: «Мои слова → Прогресс» и «Лексика → Прогресс»

Логика метрик — документ «Padma — бизнес-логика метрик словарного прогресса». Код: `server/lexiconMetrics.mjs` (+ тест), общий компонент `src/components/WordProgress.tsx`, страницы `src/pages/words/ProgressPage.tsx` и `src/pages/teacher/lexicon/StudentProgressPage.tsx`.

Данные — два набора: журнал попыток `lexicon_attempts` (одна строка на ответ: термин, формат, направление, верно/пропуск/подсказка, источник занятия, время и день ученика) и состояние слова `lexicon_progress` (Mastery 0–100, этап подтверждений, первый и последний день). При первом запуске старая таблица статусов без Mastery удаляется — прогресс начинается с нуля.

`POST /api/lexicon/me/progress` `{ results: [{ id, termId, correct, format, skipped?, hinted?, sourceType, sourceId, sourceLabel, sessionId, at }] }`: `id` — UUID ответа с клиента, повтор (переотправка, двойное нажатие) не учитывается; `at` принимается в пределах последних 7 дней, иначе время сервера; без `format` (старые клиенты) — как узнавание. Неизвестные словарю слова пропускаются. Клиент копит ответы в памяти и отправляет пачками (`src/student/lexicon.ts`); пачку с ответом 400 не повторяет.

Форматы → направление и прирост Mastery за верный ответ (`FORMATS`): Понимание — Выбери перевод, Верно — неверно, Собери пару (15); Вспоминание — Тренировочные карточки (25); Аудирование — Выбери перевод · аудио, Собери слово · аудио (25); Написание — Собери слово (25), Найди слово (15). Карточки и Мемория — только активность. Пропуск = ошибка.

Mastery (`applyAttempt`, константы вверху модуля — для калибровки): повтор в тот же день даёт вдвое меньше предыдущего; верный ответ после перерыва — до ×1,5 (14 дней); подсказка — ×0,5 и не подтверждает слово; ошибка снимает 15 % (не меньше 5, не ниже 0). Потолок зависит от числа дней самостоятельного подтверждения с растущей паузой (0, 1, 2, 4 дня): 30 / 40 / 70 / 89 / 100 — «Освоено» не раньше четвёртого такого дня. Перерыв в занятиях Mastery не снижает.

Метрики (`GET /api/lexicon/me/metrics?days=7|28|90` — свои; `GET /api/lexicon/students/:id/metrics?days=&source=` — учитель своих учеников, администратор всех; `source`: `homework`, `homework:<id>`, `collection[:<id>]`, `topic[:<subtopicId>]`, ответ дополнительно содержит `sources` — источники, где ученик занимался):

- «Освоено» / «Закрепляется» — текущее число слов по Mastery, период не влияет; с источником — слова, с которыми работали в нём.
- «Новые слова» — слова, впервые попавшие в упражнение за период.
- «Серия дней» — подряд дни с хотя бы одной попыткой; сегодня без занятий серия ещё держится; источник не влияет.
- «Активность» — попытки и уникальные слова по дням.
- «Успешность» — по каждому слову и направлению последние 5 ответов без подсказки с весами 1…0,6 (новее — значимее), затем среднее по словам, с которыми работали за период. Меньше 5 ответов — `null` («Недостаточно данных»), меньше 5 слов или 20 ответов — `lowSample` («значение предварительное»).
- «Слова, к которым стоит вернуться» — неосвоенные слова с ошибками, по возрастанию Mastery (до 10).

«Лексика → Прогресс»: фильтры Группа (группы банка слов, `/api/vocab/groups`, сужают список учеников), Ученик, Период (7 дней / 4 недели / 3 месяца), Источник (все, ДЗ и конкретное ДЗ, коллекции, темы словаря — конкретные значения из `sources`). Коллекции ученика пока локальные и состоят из слов банка учителя, поэтому в журнал не попадают. «Сегодня → слова, к которым стоит вернуться» пока на локальных статусах браузера.

Часовой пояс ученика: `users.timeZone` (IANA, по умолчанию `Europe/Moscow`), поле «Часовой пояс» в профиле ученика и в карточке ученика у учителя (`PATCH /api/profile`, `POST|PATCH /api/users`; без поля в запросе значение сохраняется, неизвестный пояс — 400). По нему считаются дни практики, серия и «новые слова за период» (`server/timezone.mjs`: `localDay`, `addDays`). Расписание уроков и сроки ДЗ по-прежнему по Москве.

## Оформление: Liquid Glass и фон

Стеклянные поверхности задаются переменными в `src/styles/global.css` (`--glass-fill`, `--glass-fill-strong`, `--glass-blur`, `--glass-rim`, `--glass-shadow`) и классами `.glass` / `.glass-panel`. Важно: при значении через `var()` Lightning CSS оставляет только последнее из пары `backdrop-filter` / `-webkit-backdrop-filter`, поэтому префиксная версия пишется первой, стандартная — последней. `global.css` подключается после CSS компонентов, поэтому переопределения поверх `.glass-panel` требуют более точного селектора.

`server/appearance.mjs`: таблица `appearance` (owner = id преподавателя или `default`, изображение BLOB до 5 МБ JPG/PNG/WebP с проверкой сигнатуры, размытие 0–60, осветление 0–90). Преподаватель видит свой фон, ученик — фон своего преподавателя, остальные и страница входа — фон по умолчанию. API: `GET /api/appearance` (активный фон и права), `PUT|DELETE /api/appearance/mine` (только роль teacher), `PUT|DELETE /api/appearance/default` (owner/admin), `GET /api/appearance/image/:owner?v=` (версионированный URL, долгий кэш; фон по умолчанию и `GET /api/appearance/public` доступны без входа). Браузер перед загрузкой уменьшает фото до 2560 px и перекодирует в JPEG. Настройки — раздел «Оформление» на странице «Настройки» преподавателя; ползунки показывают предпросмотр на всём сайте до сохранения. `server/appearance.test.mjs` проверяет права, видимость фона по ролям, валидацию и сохранение настроек без замены изображения.
