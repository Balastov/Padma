# Правила работы с Padma

- Правила действуют для всего репозитория. Общайся с пользователем по-русски.
- Перед работой прочитай README.md и DEV.md; проверь git status, текущую ветку и diff.
- Сохраняй незакоммиченные изменения пользователя. Не выполняй reset --hard, clean, принудительный checkout или переписывание истории без явного разрешения.
- Работай сразу в main: коммить и пушь в origin/main, если пользователь просит залить/запушить. Отдельные ветки feat/<тема>, fix/<тема> или docs/<тема> создавай только когда пользователь явно попросит. Не переключай ветку с чужими изменениями без безопасного плана.
- Коммит и push выполняй по просьбе пользователя («залей», «в main», «запушь» и т.п.). Push в main может запускать автодеплой.
- Не изменяй remotes и настройки хостинга без необходимости задачи.
- Стек: React, TypeScript, Vite, React Router, обычный CSS, Lucide; пакетный менеджер npm, источник версий — package-lock.json.
- Страницы находятся в src/pages, компоненты с соседними CSS — в src/components, общие стили — src/styles/global.css, изображения — src/assets.
- Сохраняй существующий стиль TypeScript: функциональные компоненты, типизированные props, отдельные type-imports, одинарные кавычки, без точек с запятой.
- Сохраняй русский интерфейс, существующий дизайн и адаптивность, если задача не требует их изменения.
- Делай минимальные изменения по задаче. Не обновляй зависимости и не добавляй библиотеки без обоснованной необходимости.
- Не редактируй dist и node_modules вручную. Обновляй lockfile через npm только при изменении зависимостей.
- Приложение использует Node.js backend и SQLite: авторизация, пользователи, расписание, чат и ДЗ сохраняются на сервере. Ограничения прав должны проверяться API.
- Не записывай секреты в код, документацию, git или вывод команд. VITE_* попадает в клиентскую сборку и не подходит для секретов.
- Локальный запуск использует значения конфигурации по умолчанию. Серверное окружение описано в DEV.md и DEPLOY.md; примеры env содержат только безопасные значения.
- После изменений кода выполняй npm run lint и npm run build; после изменения интерфейса проверяй затронутые сценарии в браузере на мобильной и широкой ширине.
- Выполняй npm test для серверной логики. Тесты используют отдельные временные базы; не запускай изменяющие тесты на рабочей базе. Не выдавай сборку за тестирование поведения.
- Перед завершением проверь git diff --check и итоговый diff. Сообщи, что изменено, какие проверки выполнены и какие ограничения остались.
