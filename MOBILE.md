# Тестовая Padma для iPhone и Android

Это **онлайн-прототип для установки с компьютера**, версия 0.1.0. Он открывает
`https://www.padma.ru` внутри Capacitor 8.6.0. Аккаунты, расписание, чат, ДЗ и
прогресс общие с сайтом. Все действия выполняются на действующем сервере:
пользуйтесь тестовыми аккаунтами для проверок, создающих или изменяющих данные.

Приложению нужен интернет. Исходники из `src/` пока не включаются в мобильную
сборку: приложение показывает **опубликованную версию сайта**. Изменения сайта
появляются в приложении после его перезагрузки; изменения нативного проекта
требуют пересборки и переустановки. Коммит и публикация сайта для установки этого
прототипа не нужны.

`server.url` в Capacitor предназначен для разработки, поэтому эту конфигурацию
не следует отправлять в App Store или Google Play. Для магазинной версии нужно
включить frontend в сборку, отдельно реализовать доступ к API и авторизацию,
нативные уведомления и пройти проверки платформ.

## Установить на свой iPhone с MacBook

Нужны Xcode 26+ с iOS SDK, Node.js 22.13+ и iPhone с iOS 15+. При первом открытии
Xcode может предложить установить необходимые компоненты. Для сборки на
физический iPhone симулятор скачивать не обязательно.

Из корня репозитория:

```bash
npm ci
npm run mobile:ios
```

Если зависимости уже установлены, достаточно второй команды. Она синхронизирует
проекты и откроет `ios/App/App.xcodeproj` в Xcode. CocoaPods не нужен:
используется Swift Package Manager. Первый запуск требует сети для загрузки
нативного Capacitor; версия закреплена.

1. Подключите разблокированный iPhone кабелем. Подтвердите «Доверять этому
   компьютеру» на iPhone, если появится запрос.
2. В **Xcode → Settings → Accounts** добавьте свой Apple Account. Пароль и коды
   подтверждения вводите только в системный интерфейс Apple.
3. В навигаторе Xcode выберите синий проект **App**, затем **TARGETS → App →
   Signing & Capabilities**. Включите **Automatically manage signing**, в **Team**
   выберите свою **Personal Team** или команду разработчика. Исходный Bundle
   Identifier — `ru.padma.app.test`. Если он занят, задайте свой уникальный.
4. В верхней панели выберите схему **App** и свой iPhone вместо симулятора.
5. На iOS 16+ при запросе включите **Настройки → Конфиденциальность и безопасность
   → Режим разработчика**, перезагрузите телефон и подтвердите включение.
6. Нажмите **▶ Run** в Xcode. Если iPhone попросит доверие разработчику, выполните
   указанный им шаг в **Настройки → Основные → VPN и управление устройством**.
7. Откройте **Padma Тест** на iPhone и войдите в аккаунт Padma. После установки
   MacBook и кабель для обычного запуска не нужны; интернет по-прежнему нужен.

Бесплатной Personal Team достаточно для личного тестирования. Подпись действует
7 дней: затем снова подключите iPhone и нажмите Run, чтобы переустановить
приложение. Это ограничение Apple, не срока сессии Padma. TestFlight и публикация
в App Store требуют участия в Apple Developer Program.

Не сохраняйте пароли, приватные ключи или профили подписи в репозитории.
Xcode хранит аккаунт и сертификат локально. Team выбирается в настройках проекта
в Xcode.

## Android

Проект находится в `android/`. Нужны Android Studio, совместимый JDK и Android
SDK для закреплённых в `android/variables.gradle` версий. На Mac, где подготовлен
этот прототип, JDK и Android SDK пока не установлены; Android-сборка и поведение
на устройстве ещё не проверены.

```bash
npm run mobile:android
```

В Android Studio выберите подключённое устройство с USB debugging или эмулятор и
нажмите Run. Для установки debug-сборки на своё устройство Google Play не нужен.
Сборка APK из терминала после настройки Android SDK:

```bash
cd android
./gradlew assembleDebug
```

APK появится в `android/app/build/outputs/apk/debug/`. Ключи release-подписи не
создавались. Вложения и переходы во внешние приложения на Android требуют
отдельной проверки перед передачей Android-сборки тестировщикам.

## Что добавлено

- Отдельная иконка **Padma Тест** и стартовый экран с логотипом Padma.
- HTTPS без разрешения незашифрованного трафика и без произвольного списка
  доменов, которым доступна навигация внутри приложения.
- Локальный экран ошибки соединения с кнопкой повторного открытия Padma.
- iOS: верхний край интерфейса ниже строки состояния; нижние безопасные отступы
  использует существующий интерфейс сайта; возврат жестом назад.
- iOS: ссылки на Tolk открываются через систему. Вложения с `/api/files/`
  скачиваются внутри WKWebView с сохранением HttpOnly-сессии и открываются
  системным Quick Look, откуда их можно сохранить или отправить. Временная копия
  удаляется при закрытии просмотра.
- iOS: описания доступа к камере и фотографиям для выбора вложений и аватара.
- Сервер, его проверка прав, cookies и база данных не изменялись.

Нативные push-уведомления, офлайн-задания и синхронизация без сети в прототип не
входят. Наличие веб-уведомлений на сайте не означает их поддержку в WKWebView.
Видеоурок пока открывается по существующей ссылке Tolk, не в нативной видеокомнате.

## Проверки перед передачей тестировщикам

Сборка не заменяет проверку поведения на телефоне. На тестовых аккаунтах проверьте:

1. Вход, перезапуск приложения с сохранением входа, выход; неверный пароль.
2. Расписание и переключение дат в кабинетах ученика и преподавателя.
3. Чат: отправка и получение сообщения, клавиатура, выбор и открытие вложения.
4. ДЗ: отправка ответа с PDF/фото, просмотр вложения, возврат и повторная сдача.
5. Тренажёр: озвучка, ответ, завершение и сохранение прогресса после перезапуска.
6. Переход в Tolk и возврат в Padma.
7. Холодный запуск без интернета → экран ошибки → восстановление сети →
   «Попробовать снова». Пропавшая сеть в уже открытой форме обрабатывается сайтом.
8. Портретная и альбомная ориентации: вырез экрана, нижнее меню и диалоги.

Проверка сборки iOS без подписи (не устанавливается на телефон):

```bash
npm run mobile:sync
xcodebuild -project ios/App/App.xcodeproj -scheme App \
  -configuration Debug -destination 'generic/platform=iOS' \
  -derivedDataPath /private/tmp/padma-ios-build \
  CODE_SIGNING_ALLOWED=NO build
```

Изменения `capacitor.config.ts` и локального экрана `mobile/www/` переносит
`npm run mobile:sync`. Генерируемые конфигурации и копии web-ресурсов исключены
из git; сами нативные проекты и исходные ресурсы должны храниться в репозитории.
`dist` не используется этим онлайн-прототипом.
