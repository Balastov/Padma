# Публикация Padma на Ubuntu

## Сервер

- Сайт: https://www.padma.ru и https://padma.ru.
- SSH: `ssh -i ~/.ssh/id_ed25519 user1@176.108.246.144`.
- Node.js 24.21.0 установлен отдельно в `/opt/padma/node-v24.21.0-linux-x64`; ссылка `/opt/padma/node`. Архив проверен по SHA256 с nodejs.org.
- Backend: `padma.service`, пользователь `padma`, слушает только `127.0.0.1:3001`.
- Релизы: `/var/www/padma/releases/<UTC>-<commit>`; активный — `/var/www/padma/current`.
- Nginx раздаёт `current/dist`, запросы `/api/` передаёт backend. HTTPS-сертификат и настройки соседних сайтов сохраняются.
- Постоянная база и вложения: `/var/lib/padma/padma.sqlite`, доступны только системному пользователю Padma и root.
- Окружение службы: `/etc/padma/padma.env`. Безопасный образец — `deploy/padma.env.example`.
- Проверка работы: GET `/api/health`. Не выдаёт данные пользователей.
- Журнал backend: `sudo journalctl -u padma`. Nginx: `/var/log/nginx/padma.access.log`, `padma.error.log`.

## Первичная установка

Нужны Node.js по указанному пути, пользователь padma, каталоги `/var/lib/padma` и `/var/lib/padma/backups` с владельцем padma и правами 0700, начальная база с правами 0600. Начальные учётные записи переносятся защищённо вне git, только с хешами паролей и без локальных сессий. Исходный документ и открытые пароли на сервер не отправляются.

Первый переход со статического сайта выполняется тем же `deploy/activate.sh`: он сохраняет старую ссылку и конфигурацию Nginx для отката. Старая статическая версия: `/var/www/padma/releases/20260916-506b187`.

## Обновление

После коммитов и разрешения на публикацию:

```bash
bash scripts/deploy.sh
```

Скрипт требует чистую рабочую копию, выполняет lint, тесты и сборку. Загружает только новый релиз, повторяет тесты на серверном Node, делает копию существующей базы, переключает current и перезапускает только Padma. Проверяет backend, Nginx и HTTPS. При ошибке активации возвращает прежнюю ссылку и конфигурацию Nginx. База при обновлениях не заменяется.

Опционально `PADMA_SSH_KEY` и `PADMA_SSH_TARGET` задают ключ и SSH-адрес. Пароли, ключи, база, node_modules и env не входят в архив или git.

## Автодеплой из main

Настроен 17 сентября 2026. Сервер проверяет публичный репозиторий Balastov/Padma раз в минуту через padma-autodeploy.timer. GitHub Actions и секретные ключи не требуются; после закрытия репозитория потребуется отдельно настроить доступ на чтение.

Любой push/merge в main теперь разрешает автоматическую публикацию этого кода. Работайте в отдельных ветках и отправляйте в main только готовые изменения. Сам автодеплой не создаёт коммитов и не отправляет код в GitHub.

Сборка запускается пользователем padma-build без доступа к рабочей базе: npm ci → lint → test → build → npm prune --omit=dev. В релиз входят `dist`, `server`, production `node_modules` (сейчас нужен `web-push` для push-уведомлений), `deploy` и служебные файлы. `activate.sh` дополнительно проверяет `node_modules/web-push` и при отсутствии ставит production-зависимости через npm. Затем: резервная копия SQLite, переключение, рестарт Padma, проверки API/HTTPS, откат кода при ошибке. База не заменяется и не откатывается автоматически. Несовместимые миграции требуют отдельного плана.

Повторные запуски защищены блокировкой. Если main изменился за время сборки, устаревшая версия не активируется. Неудачный commit не публикуется повторно автоматически до исправления в main или явного повторного запуска. Успешно опубликованный commit повторно не собирается.

Управляющий скрипт: /usr/local/sbin/padma-autodeploy. Его исходник и systemd units сохранены в deploy/padma-autodeploy.*; изменение этих файлов в git само по себе не переустанавливает управляющую службу. Состояние: /var/lib/padma-autodeploy/deployed и failed; SHA также записывается в REVISION внутри каждого нового релиза. Кэш сборки — /var/cache/padma-autodeploy. Сборки ограничены одним CPU и 1500 МБ памяти. Старые релизы сохраняются для отката; контролируйте свободное место.

```bash
# Статус, расписание, журнал
sudo systemctl status padma-autodeploy.service padma-autodeploy.timer
sudo journalctl -u padma-autodeploy.service -n 100 --no-pager
sudo systemctl list-timers padma-autodeploy.timer

# Проверить main сейчас
sudo systemctl start padma-autodeploy.service

# Повторить ранее неудачный commit после устранения причины
sudo env PADMA_RETRY=1 /usr/local/sbin/padma-autodeploy

# Приостановить дальнейшие автоматические публикации
sudo systemctl disable --now padma-autodeploy.timer
# Это не отменяет уже начавшийся деплой; перед ручной работой дождитесь окончания службы.

# Возобновить
sudo systemctl enable --now padma-autodeploy.timer
```

Перед ручным deploy или откатом приостановите таймер и дождитесь завершения текущего запуска. Откатывайте через новый revert-коммит в main либо оставляйте таймер выключенным до устранения причины. Уведомления о сбоях пока не подключены — результат доступен в журнале systemd.

## Резервные копии

`padma-backup.timer` запускает ежедневную копию в 03:00 UTC (06:00 Москва, плюс задержка до пяти минут); пропущенный запуск выполняется после старта сервера. `scripts/backup.mjs` использует SQLite VACUUM INTO и проверяет целостность. Хранятся последние 14 снимков в `/var/lib/padma/backups`, права 0600. Копия также создаётся перед обновлением. Снимки находятся на том же сервере; внешнее резервное хранилище пока не настроено.

```bash
sudo systemctl start padma-backup.service
sudo systemctl list-timers padma-backup.timer
```

## Откат

Для предыдущей полной версии: вернуть current на сохранённый релиз и выполнить `sudo systemctl restart padma`. Базу не откатывать автоматически: это может удалить новые работы учеников. При несовместимом изменении схемы потребуется отдельный план восстановления.

Для возврата к первоначальной статической версии нужно также вернуть конфигурацию Nginx из `/var/backups/padma/<UTC>/nginx.conf`, остановить только `padma.service`, выполнить `sudo nginx -t` и `sudo systemctl reload nginx`. Нельзя возвращать архив всего Nginx поверх более поздних настроек других сайтов.

Не останавливать nginx, task-tracker, BadWords_4 и engspring-bot ради обновления Padma. Сертификат продлевается существующим certbot.timer через `/var/www/padma/acme`.

## Проверка публикации

После активации проверить `/api/health`, вход обеих начальных учётных записей, Secure/HttpOnly cookies, защищённый API, загрузку JS/CSS и соседний сайт mispring.ru. Пароли в вывод проверки не включать.
